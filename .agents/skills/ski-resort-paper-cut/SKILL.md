# スキー場・ホテルのペーパーカット

実景の特徴が分かる、人物のいない冬のリゾート画像を作る。地形・建物を調査で捉え、紙の質感と色調をシリーズで揃える。精密なコース案内図としては扱わない。

## 入力と進め方

- スキー場名を起点に進める。ホテル名、参考URL、用途、縦横比、参照画像があれば使う。既に分かることを聞き直さない。
- Snowcationでは対象の`src/content/resorts/<slug>.mdx`から施設名・ホテル・公式リンク・現在の画像を確認する。記事の情報は調査の入口として使い、外観を写真で確かめる工程は省かない。
- 現在の依頼を優先する。新規画像は原則として1施設1枚の、ホテルとゲレンデが同居する横長の構図にする。複数施設を1枚のコラージュにしない。
- 新規画像の縦横比は、指定・配置先の要件・採用済みシリーズの順に決め、いずれもなければ3:2とする。既存画像の編集は元の比率を維持する。
- 「プロンプトだけ」「調査だけ」は指定された段階まで行う。画像生成を依頼された場合は、調査とプロンプト作成で止めず、生成・目視確認まで行う。
- 画像生成・編集には利用環境の画像生成ツールを使い、`imagegen`スキルがあればその実行手順に従う。画像生成ツールが使えなければ、調査結果と完成したプロンプトを渡し、生成は未実施と伝える。無断で有料APIへ切り替えない。

## 作風

`dreamy, layered paper-cut 3D illustration`を基調とする。

- 紙の繊維、切り口、重ねた厚み、層の間に落ちる柔らかな影を見せる。雪、山、木、建物を一貫した紙の素材で表現する。
- 全体の構図と輪郭は簡潔にし、細部の密度を距離に応じて落とす。**手前〜中景の森は個々の木や木の群れを重ね、遠くの山は大きな紙の面でよい。** 遠景の森も小さなシルエットへ整理できる。全域を同じ密度で描き込む必要はない。
- 雪の白、淡い青、くすんだ青の影を主体にし、淡い桃色〜杏色の光、ホテルの窓の暖色を添える。実在施設の特徴的な屋根やキャビンの色は残す。夕方の柔らかい光を既定とし、太陽や紙の雲は構図に合う場合に使う。
- 山の輪郭は現地の写真から単純化する。日本のスキー場を一律にアルプス風の尖峰へ変えず、特徴的な山を一律になだらかにもしない。
- 実在ホテルの棟の構成、屋根、外壁色、窓のまとまりを残し、細かな窓枠・設備を省略する。モダンなホテルを既定にするのは、実在施設を指定しない架空のリゾートだけとする。
- 人物、スキーヤー、小さな人影は入れない。既定では文字、ロゴ、透かしも入れない。雰囲気づくりだけを目的とする川・橋・建物を足さない。湖など、その場所を特徴づける実在の水景は描いてよい。

### 作例の使い方

[references/reference-images.md](references/reference-images.md)からリポジトリ内の採用済み画像を選び、実際に開いて確認する。基本は`src/assets/grandeco.webp`を1枚参照する。別の視点が必要ならネコマまたはたざわ湖を追加する。`src/`と`output/`で始まるパスはリポジトリルート基準とする。

新規生成では、作例から紙の素材、色調、光、細部の整理を引き継ぐ。作例に写る別施設のホテル・ゴンドラ・湖を新しい施設へ移植しない。作例の樹種（グランデコの針葉樹など）も引き継がず、森は現地の調査で決める。作例は現地の正確さを証明する資料ではない。

参照画像が取得できない環境でも、上記の文章を使って新規生成を進める。厳密に作風を合わせる必要があれば、取得できた作例を画像入力として渡す。URLを書いただけで画像を参照させたことにはしない。

## 新規作成

### 1. 公式資料を調べ、画像を目視する

公式スキー場サイトの冬の景観写真・コース図と、描くホテルの公式外観写真を確認する。公式資料だけでは形が分からない場合は、自治体や観光協会の写真を補う。検索結果の説明文や過去のアシスタントの回答だけで外形を確定しない。

ページを開くだけでなく、写真やコース図の画像そのものを見る。PDFなら該当ページを表示する。画像表示ができなかった項目は未確認とし、見たことにして補わない。

| 調べる対象 | 画像に必要な情報                                                                 |
| ---------- | -------------------------------------------------------------------------------- |
| 山・斜面   | 山の輪郭、コースの広がり、山頂とゲレンデの関係、見上げる／見下ろす方向           |
| 森         | 斜面を囲む範囲、木の形・密度、雪面との境界、針葉樹と広葉樹の割合と標高による違い |
| ホテル     | 棟の構成、屋根の形・色、横幅と高さ、外壁色、特徴的な窓、ゲレンデとの位置関係     |
| リフト類   | チェア／ゴンドラの区別、椅子の人数、キャビンの輪郭・窓・色、経路と終点、駅の形   |
| 眺望       | 湖、海、特徴的な山などの有無と、実際に見える方向                                 |

ホテルが指定されていなければ、隣接する代表的なホテルが明確な場合に採用する。適切なホテルが確認できなければ、実在するスキーセンターを添えるか、ゲレンデを主役にする。離れたホテルを麓に直結しているように描く必要がある場合は、構図を分けるか、再構成であると明記する。

描く設備について現行情報と古い写真が食い違う場合は、対象時期に合う資料を優先する。ユーザーが描画上の設備を明示した場合はその指定を使い、営業状況の事実と混同しない。

#### 森の樹種を決める

針葉樹が多いか、葉の落ちた広葉樹が多いかで、スキー場の雰囲気は大きく変わる。冬の写真（公式のゲレンデ写真、Wikimedia Commons など）で次を確かめ、調査メモに残す。

- 針葉樹と広葉樹のおおよその割合。冬の広葉樹は葉が落ち、枝の線が見える（白樺なら白い幹）。
- 標高による違い。上部だけ針葉樹になる、樹氷になる（アオモリトドマツなど）、山頂付近は低木になる、など。公式の「樹氷」「ブナ林」のような言い方も手がかりにする。
- 写真の撮影時期。冬以外の写真で冬の葉の有無を決めない。

写真で決まらなければ、決まった範囲だけをプロンプトに書き、樹種を断定しない。

施設を識別する地形、建物、特徴的な設備の形が揃ったら調査を終える。資料の数を増やすことを目的にしない。

### 2. 配置の下絵を作る

リフトの経路と終点、コース、ホテルの位置は、文章だけで渡すと生成モデルが崩す（ありえない場所を通る、途中で途切れる）。OSMと地理院の標高から構図の下絵を作り、生成時に渡す。`output/resort-research/<slug>/`に`guide.png`が既にあれば、それを使う。

```bash
node .agents/skills/ski-resort-paper-cut/scripts/layout.mjs --slug <slug> --bbox <西,南,東,北> --hotel way:<OSMのID> [--exclude <way ID,...>] [--view-from <方位>]
```

- `--bbox`はゲレンデ全体を含む範囲にする。施設の座標はNominatim（User-Agentを付ける）で引ける。
- ホテルはOSMに`tourism=hotel`の建物があれば`way:<ID>`で渡す。無ければ緯度経度にする。名前の近い駐車場や別の宿を取り違えやすいので、`map.png`で乗り場との位置関係を確かめる。
- 隣のスキー場のリフトやコースが入ったら、`--exclude`で外す。所属は自動で判定しない。`layout.json`の名前と`map.png`の位置で見分ける。
- 視点は代表の下り方位から斜面を見上げる。主役を変えたいときは`--view-from`で回す。
- `guide.png`を開き、見えているリフトが駅から駅まで続き、ホテルが正しい位置にあることを確かめてから進む。

下絵の色線・文字・駅とホテルの箱は記号であり、完成画像に残さない。

#### 見えないリフト・コースは省略する

大きなゲレンデでは、視点から尾根の向こうになるリフトやコースがある（ネコマを南から見れば北エリアは見えない）。下絵は地形に隠れる部分を描かない。下絵に写っていないリフト・コースは画像でも描かず、尾根の向こうへ線を回り込ませない。`layout.json`の見えている割合で、どれが隠れているかを確かめる。全部を見せるために視点を変える必要はない。

#### 駅を描き、別のリフトの駅と繋げない

リフトごとに乗り場と降り場の駅を描く。見えているリフトの端で駅が省かれると、線が途中で切れて見える。駅を省いてよいのは、地形や森で端が自然に隠れるときだけとする。

駅の形はリフトの種類で違う。山小屋のような建物で一律に描かない。

| 種類                   | 乗り場                                                         | 降り場                                   |
| ---------------------- | -------------------------------------------------------------- | ---------------------------------------- |
| ペアリフト（2人乗り）  | 屋根のない鉄骨の滑車台が柱の上に載り、横に小さな係員小屋がある | 乗り場と同じ                             |
| クアッドなど高速リフト | 建物になっていることが多く、屋根の形に特徴がある               | 屋根のない滑車台の横に小屋がある形が多い |
| ゴンドラ               | 必ず建物（屋根つき）がある                                     | 同じ                                     |

形は写真で確かめる。ペアリフトは上の典型でよいが、写真があれば滑車台の色や看板などを合わせる。クアッドの乗り場の建物は、写真で屋根の形を調べて引き継ぐ。ゴンドラの駅舎は必ず写真で調べ、建物の形の雰囲気を引き継ぐ。写真で確かめられなかった駅は、上の典型で描き、調査メモに未確認と書く。公式サイトに無ければ、Wikimedia Commons の写真も使える。

あるリフトの降り場と別のリフトの乗り場は、近くにあっても別の駅として描き、ケーブルを一本に繋げない。`layout.json`の駅どうしの距離がほぼ0（共通の乗り場）のときだけ、1つの駅にまとめてよい。

### 3. 特徴と構図を決める

その施設らしさが伝わる特徴を2〜4個選ぶ。全コース、全棟、全リフトを描く必要はない。視点とリフト・ホテルの位置関係は下絵に従う。コースの本数を減らす、森で一部を隠すといった紙の絵としての単純化はしてよい。

主役はゲレンデ（斜面・コース・森）と山であり、リフトと駅は脇役である。リフトは違和感なくそこにあればよい。

- 大きさは下絵の遠近に従う。遠くのリフト・駅・椅子は山に対して小さく描き、手前でも下絵より大きくしない。
- 写真は形を確かめるために使う。写真で確かめた要素（乗り場など）を、写真の写り方に合わせて大きく描いたり、手前へ引き寄せたりしない。
- コースは森を抜ける白い帯として、下絵のコースの広がりと曲がり方が伝わるように描く。斜面全体を一様な雪原にしない。

調査メモには次を分けて残す。

- **確認済みの形・位置関係**：資料URL、目視した写真・図、確認日とともに記す。
- **絵としての再構成**：省略、縮尺調整、視点の選択などを記す。現実の隣接関係や眺望を誤認させる変更は避ける。
- **未確認**：画像が見られない、色が写真で異なるなど。重要でなければその細部を省略する。

特徴が定まったら、採用する要素を短く伝えて制作を続ける。施設の同定など、結果を大きく左右する曖昧さだけを質問する。

### 4. プロンプトを組み立て、生成する

[references/prompts.md](references/prompts.md)の雛形を使い、共通の作風と施設固有の特徴を分けて指定する。入力画像の役割も「作風」「ホテルの外形」「配置の下絵」「編集対象」に分ける。生成ツールが入力画像を受け取れる場合は、説明と対応づけて実際に渡す。

作例の特徴を使う施設では[references/resort-notes.md](references/resort-notes.md)も読む。そこにある過去の描画指定は守り、現地の外観は実行時に確認する。

## 部分修正

既存の絵を変える依頼は編集として扱い、対象画像を開いてから進める。「元の位置に戻す」など比較が必要な場合は、その基準となる画像も見る。対象または基準画像を取得できず、正確な変更箇所が分からない場合だけ再添付を求める。

編集プロンプトには、**変更する部分・維持する部分・位置の基準**を明記する。ホテル、森、光、構図など既に評価された要素を固定し、一度に依頼された変更を施す。単なるケーブルの接続修正で、リフト全体の経路を設計し直さない。

リフトは支柱から次の支柱・終点・画面外・自然な遮蔽まで線が続く構造にする。正しい終点を「途切れ」と取り違えない。上端と下端を別々に扱い、ユーザーが指定した終点を山頂まで延長しない。元の画像は残し、新しい版として保存する。

## 生成後の確認と完了

実際の出力画像を開き、次を目視する。

- 選んだ特徴から、その施設の雰囲気が伝わる。
- 紙の厚み・切り口・柔らかな影が残り、写真や光沢のある模型へ変わっていない。
- 手前〜中景の森に重なりがあり、遠景は必要に応じて大きな紙の面へ整理されている。針葉樹と広葉樹の割合と標高による違いが調査メモに合う。
- ホテルの外形と、リフト／ゴンドラの形・色・規模感が採用した資料・指定に合う。
- リフトの線が不自然に消えず、終点を越えた延長や建物を貫く経路がない。
- 下絵と並べて、見えているリフトの本数・経路・上下の駅とホテルの位置が対応する。下絵に無いリフトや、尾根の向こうへ回り込む線がない。下絵の記号（色線・文字・箱の色）が残っていない。
- リフト・駅・椅子の大きさが下絵の遠近に合い、遠くのものが山に対して大きすぎない。写真で確かめた要素が誇張されていない。コースが森を抜ける帯として読める。
- 見えているリフトの両端に駅があり、リフトの種類と写真に合う形をしている（ペアリフトを山小屋で描かない）。自然に隠れる端は除く。別のリフトの降り場と乗り場が1つの駅やひと続きのケーブルになっていない。
- 人物らしい微小な形、不要な文字、依頼していない川や建物がない。
- 編集では、元画像と比較して変更対象以外が維持されている。

明確な破綻があれば、その箇所を限定して直す。合格した画像を際限なく作り直さない。未解決の違いは短く伝え、ピクセル単位の維持を確認せず保証しない。

プロジェクト用の制作では既存の出力先を使う。指定がなければ`output/resort-images/<resort-slug>/`に、選んだ画像、調査メモ、最終プロンプトを残す。画像は既存ファイルを上書きせず版を付ける。チャット上のプレビューでは、その環境の保存方法に従う。

Snowcationへの組み込みまで依頼された場合は、採用画像を既存のWebP形式・命名に合わせて`src/assets/`へ配置し、対象MDXの`image`と`imageAlt`を整える。画像の制作だけを依頼された段階では、現在掲載している画像を差し替えない。

最終報告は、完成画像、取り入れた特徴、主な出典、残る制約を短く示す。ローカル保存した場合は実際の保存先も示す。プロンプトのみの依頼では、コピーして使える完成したプロンプトと調査根拠を渡す。
